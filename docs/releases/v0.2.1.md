# v0.2.1 — 首页与四象限看板

## What's Changed

### ✨ Features

* **新首页：启动默认视图**。顶部统计条（今日已专注 / 今日剩余估计 / 逾期 / 今日完成）
  + 近 7 天专注柱状图，下方看板区在四象限与长期池两个 tab 之间切换。职责是纵览与
  分流；执行（计时、Finish Day）仍在今日页。

* **四象限看板**：全部未完成任务按"重要 × 紧急"投进四格，是所有任务的总览视图。
  "不重要不紧急"格是未分流任务的天然收集池。
  - 拖拽即改期、改重要：**上下跨行拖 = 切换重要**，**左右跨列拖 = 改截止日期**
    （拖进紧急列 = 截止今天，拖出 = 截止今天 + 阈值 + 1 天）。
  - 每格有"本周完成 N 个"吞吐量徽章与格内手动排序（顺序按格持久化）。

* **长期池看板**：预置看板，收纳"未定日期"与"已定远期（14 天以外）"两类长期任务，
  各分区独立手动排序。

* **重要成为真正的任务字段**：`Task.isImportant`，任务卡片上的星标一键切换，
  不再依赖隐藏的系统标签。

* **紧急改为派生属性**：不再存储，由截止日期推导——dueDay 距今 ≤ N 天（含逾期）
  即紧急。阈值 N 可在设置新的"首页看板"分区里调整（默认 2 天，范围 0–30），
  调整立即重排看板。

* **任务卡片显示子任务进度**：有子任务时展示"子任务 3/5"徽章。

* **设置页立即显示当前版本**：版本号在启动时从本地安装包读取，不再等一次更新检查
  之后才出现。

### 🔄 Data & Migration

* **零迁移步骤**：旧 `data.json` 直接打开——`isImportant` 与紧急阈值都由 schema
  默认值回填。

* **旧系统标签自动清理**：启动时把遗留的隐藏系统标签 `EM_IMPORTANT` 折叠进
  `isImportant` 字段，并连同 `EM_URGENT` 一起从所有任务与标签库里删除。备份导入
  路径同样处理，旧备份不会复活这两个标签。两个标签在界面上从不出现，因此没有
  用户可见信息丢失。详见 [ADR 0006](../adr/0006-importance-is-a-field-not-a-system-tag.md)。

* docs: add ADR 0006 — 重要是任务字段，不是系统标签

## 已知缺口

* **四象限拖拽会覆盖原截止日期**（"拖拽即改期"是设计决定，见 ADR 0007）：拖进
  紧急列把 dueDay 改成今天，拖出改成"今天 + 阈值 + 1"。原本截止下周的任务拖一下
  就丢了原日期，撤销只能手动改回。
* **"本周完成"实际是滚动 7 天窗口**（今天往前数 6 天），不是自然周。
* **看板拖拽只支持鼠标**：从卡片左侧 grip 手柄拖起，暂无键盘操作。

## 技术说明

看板是一条保存的分组规则，把同一份任务投影成列——任务不归属于看板，可以同时
出现在多个看板里（ADR 0007）。紧急度是查询期派生值，不是存储字段；格内手动排序
按 `quadrant:<格>` / `longTerm:*` 等 viewKey 持久化，排序逻辑抽成了可复用的
`useManualOrder` hook，今日页等既有视图的排序行为不变。

图表新依赖 [recharts](https://recharts.org/)。今天已工作 / 剩余估计的口径从今日页
抽出为共享 helper，首页统计与今日页共用同一份计算。
