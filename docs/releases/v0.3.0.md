# v0.3.0 — 定时任务

## What's Changed

### ✨ 定时任务（全新功能）

* **定时任务**：新建一个定时任务，写一段 prompt 和执行目录，它会在你设定的时间点
  由 AI Agent 独立执行。支持每天、每周（指定星期几）、每月（指定几号）三种频率，
  也有「立即运行」可以随时手动触发一次。

* **任务历史**：每一次运行——不管是定时触发、手动触发还是跑失败——都留下一条记录，
  包含开始结束时间、成功失败、以及**每一次工具调用的完整轨迹**（调了什么工具、
  传了什么参数、在哪个目录跑的、结果是什么、耗时多久）。

* **重叠保护**：同一个任务上一次还没跑完时，新的触发会被跳过并如实记一条「已跳过」，
  而不是让两个 AI 同时在同一个目录里写文件。

* **运行结束发系统通知**：通知权限被拒也不影响运行记录——横幅发不出去不等于这次运行
  没发生。

### 🐛 这一版修掉的问题

定时任务是在本轮新加的功能，发布前经过了几轮代码审查，下面几条是**如果直接发布就会
遇到的真实故障**：

* **定时任务此前从未真正执行过**：调度器把任务标记为"正在运行"之后，又去检查同一个
  标记，于是每次到点都被记成"已跳过"，AI 从未被启动。界面看不出异常。
* **新建的任务永不触发**：调度表只在应用启动时建立一次，之后新建或删除的任务不生效，
  要重启应用。
* **没有设置执行目录的任务无法执行**：默认目录 `~` 未被展开，每次调用命令都失败。
* **API 密钥会明文写进数据文件**：请求头里的 `Authorization` 原样存入运行记录，而运行
  记录会随数据备份一起保留。
* **「立即运行」与定时触发会并发起两个 AI**：两者各有一份"正在运行"的记录表，撞在同一
  秒时会同时启动，各自握着全部工具权限。
* **写入文件的相对路径落在错误的位置**：界面承诺"相对于执行目录"，实际落在应用碰巧
  启动的目录。
* **「每月 31 号」会偷偷多跑三次**：2 月被悄悄收敛到 28/29 号，而界面上明确写着这个
  月会跳过。

### ⚠️ 权限说明

定时任务的工具（运行命令、发起 HTTP 请求、读写文件）默认全部开放，详见 ADR-0008。
这是为了支持无人值守运行——授权弹窗在没有人盯着的时候只会让任务卡死。代价是：**没有
运行时防线**，所以请只对你自己写得清楚的 prompt 开启定时。运行记录（上面提到的工具
调用轨迹）是这条路上唯一的追溯手段。
