# 插件界面是左栏的一个入口，点击后进入一个独立整页

Tiny-Schedule 的浏览器半边最初注册在 `conversation.view` 插槽上，于是它以「任务」「想法」两个标签页的形式出现在会话头部的标签环里，占据对话的中栏。2026-11-10 改为：**左栏（会话历史上方）一个总入口，点击后在中栏打开插件自己的整页**，页内保持「任务 | 想法」两个标签页。

## 为什么改

会话标签环里的两个页签有三个问题：

1. **它跟会话走。** 没有会话就没有界面，插件变成了"某个对话的附属功能"，而不是一份跨会话的工作状态。
2. **它抢中栏，而且是被迫抢。** 想看一眼今天要做什么，必须先打开一个会话；对话本身的阅读与任务浏览互相打断。
3. **它不是左栏的入口。** dsh 的左栏是宿主的地盘：全局面板行（插件、自动化任务）、工作区与会话历史。任务与想法本来就是"跨会话、随时可看"的东西，就该从那一列进。

## 宿主的插槽现实

dsh `0.2.2-rc.1` 的左栏（`sidebar`）是**单槽**，由 `dsh-client-ui-sidebar` 的 `SidebarRoot` 占用。它声明的子席位里，与本决定相关的有两个：

| 席位 | 形态 | 插件能拿到什么 |
|---|---|---|
| `sidebar.panellist` | list | 一行图标 + 文字，渲染在**会话历史区正上方**；点击在**中栏**打开一个面板 |
| `sidebar.panellist.actions` | list | 「更多」菜单里的一行 |

也就是说，左栏**没有**能直接塞内容的席位（`sidebar.workspaces` 是单槽且已被 `ui-workspace` 占用，影子化它会把整个工作区浏览器连同它的目录流子插槽一起弄坏）。但左栏的**面板行本来就是"打开中栏面板"的入口**——这是宿主自己的用法。

于是问题变成：左栏点一下之后，中栏打开的那个面板由谁提供。

## 决定

插件在两个席位上各注册一次：

| 席位 | 注册内容 | 关键字段 |
|---|---|---|
| `sidebar.panellist` | 左栏一行图标 + 「任务与想法」 | `id: 'tiny-schedule'`, `order: 20` |
| `main` | 中栏一个 keyed 面板：整页的「任务 \| 想法」 | `key: 'tiny-schedule'` |

这是**宿主已有的官方范式**：`dsh-client-ui-plugin-manager` 与 `dsh-client-ui-schedule` 就是这么做的（它们分别注册 `sidebar.panellist` 行 + `main` 的 `"plugins"` / `"schedules"` 键）。

两条注册**必须用同一个 id**：宿主 `ctx.layout.selectPanel(id)` 会校验 `main` 插槽里存在同 key 的条目，否则拒绝选中。宿主渲染 `sidebar.panellist` 行时自动调用 `selectPanel(id)`，所以拼错就会表现为"点了没反应"。

页内结构与之前保持一致：

- 顶层两个标签页：**任务**（内含 今日 / 四象限 / 长期池 三个投影）、**想法**（内含 收集箱 / 验证中 / 已了结）。
- 页面头部有「返回对话」按钮，走 `ctx.layout.selectPanel(null)` 把中栏交还给对话。
- 30s 轮询 `/ts/api/state`，与 agent 工具写入同步。

## 为什么不是"左栏常驻速览"

中途试过另一个方案：左栏常驻一个「任务 | 想法」速览（DOM 锚定到 `sidebar.workspaces` 出口上方），完整视图走浮层。**它被否决了**：宿主并没有"往会话历史上方塞内容"的受支持席位，那需要 DOM 级补丁（依赖渲染器写的 `data-slot="sidebar.workspaces"` 标记），宿主改名即失效；浮层又让"完整视图"藏在一个不明显的按钮后面。改用宿主自己的 `panellist` → `main` 范式后，插件不再碰宿主的 DOM，也不需要任何 DOM 级集成。

## 后果

- **插件不碰宿主的 DOM。** 没有 `data-slot` 锚点，没有 portal 宿主，没有 re-anchor 定时器。宿主升级只要 `sidebar.panellist` 与 `main` 两个席位还在、且 `selectPanel` 的语义不变，插件就照常工作。
- **左栏只有一个入口。** 速览能力（旧方案里的"勾掉一件事、写下一件事"）没有单独的位置，要用就进整页。这是取舍：少一个入口，换一个不依赖宿主内部标记的稳定集成。
- **中栏被占用时对话不在视野里**，所以页面必须提供显式的「返回对话」，且宿主侧 `selectPanel(null)` 就是回到对话的正规方式。
- `ctx.layout` 是普通服务名，插件的 `inject` 数组里写 `'layout'` 即可（`sidebar` 自己也这么写）。
- `main` 是 keyed 插槽，对话占着 `"conversation"` 键，插件占 `"tiny-schedule"`，两者并列而非互相替换。
- 升级 dsh 时（见 `docs/dsh-version-upgrade.md`）必须复核：`sidebar.panellist` 席位是否还在、`main` 是否仍是 keyed 插槽、`selectPanel` 是否仍校验同 key 条目。
